# Trailer, 60.0 s, 1920x1080, 30 fps

Read `direction.md` first. Grid: 120 BPM, bar = 2.0 s, bar N starts at (N-1) x 2.0 s. 30 bars.

**Status: built** (2026-10-28). Project `v2/trailer60/` (HyperFrames), output
`out/v2/hoocode-trailer-60s.mp4`. The timecodes below are the built ones. The edit is generated by
`v2/trailer60/build.py` from `v2/recording/cues.json` (written to `v2/trailer60/edit.json`); SFX
cues are in `v2/trailer60/events.json`, generated from the same numbers.

Footage: `out/v2/hoocode-v2-4k.mp4` (3840x2160, 30 fps, 30.1 s). The 117x32 terminal grid is
3393x2080, centred (about 224 px side margins and 40 px top/bottom at 4K), so the wide shot (1.0x)
shows the whole terminal with dark margins. Camera rects are written `{z, cx, cy}`: zoom and the
point at the screen centre, in source-frame pixels at 1080p scale (terminal grid x 112..1808,
row r centre y = 36.25 + 32.5 r). Max zoom 2.0x = 1:1 4K pixels. HyperFrames has no playback-rate
control, so the edit (cuts, speed ramps, holds) is baked frame-exact into a 4K plate
(`build.py --plate`); the composition only moves the camera over it.

"Clip f" = frame of the 4K clip (clip time = f / 30).

## 5. Notes

- Deviations from the first draft of this doc (made to fit the real cue times without moving the
  grid): card 1 is answered on 12.5 and card 2 appears on 13.0 / is answered on 15.5 (not 11.5 /
  12.0 / 13.5), because the first test run reports `HIT` only 0.27 s after the `a` answer and there
  is no compile wait to show in bar 8; card 3 is answered on 20.5 (not 19.5). There is no
  `test result: FAILED` line on screen (cargo's output is collapsed to `… 20 earlier lines`), so
  shot 8 pans to `Command exited with code 101`. The fix and card 3 share one framing (18.0–20.6).
  The RISE bar is a slow-motion wide of the re-run with a hard cut on the drop (no push into the
  `exit 0` rect: the transcript scrolls 9 rows as the result lands). Card 8 is 1.5 s so the lockup
  can draw over black before the downbeat.
- Never shown: clip 527–533 and 690–696, where the product briefly draws `exit 0` on a shell
  step that is still running (the first, failing run would read as a pass).
- Overlays never cover cue text: plates and keycaps were placed per shot against the real frames
  (snapshots in the QA pass).
- Last frame (59.967) is the complete end card.
